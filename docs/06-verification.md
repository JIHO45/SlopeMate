# 06. 검증

작성: 2026-11-08 · 깊이: 가볍게 · 상태: 검토 대기

무엇이 동작하는지, 위험한 가정이 맞는지, 출시해도 되는지를 어떻게 확인할지 정한다. 앞 문서에서 "06에서 정함"으로 미룬 기준값도 여기서 제안한다.

## 1. 검증 방법 네 가지

| 방법 | 언제 | 무엇을 |
| --- | --- | --- |
| **기록 재생 테스트** | 판정 코드를 고칠 때마다 | 테스터 기록 파일(R22)과 기대 결과(직접 센 하강 횟수, 대기 시간)를 짝지어 저장. 코드가 같은 결과를 내는지 자동 확인. 안드로이드도 같은 파일로 확인(R48) |
| **현장 테스트** | 11월 말 개장부터 TestFlight로 | 실제 스키장에서 기록 정확도, 보존, 배터리 |
| **서버 규칙 테스트** | 서버 코드를 고칠 때마다 | Firebase 에뮬레이터로 보안 규칙과 함수의 권한 확인 |
| **수동 점검** | 출시 전 | 화면, 권한, 접근성, 심사 요건 |

## 6. 출시 체크리스트

2.0(11월 말)에는 아래 항목을 모두 확인한다. 2.0에 크루·서버가 들어가므로 서버 항목도 포함한다.

**데이터**
- [ ] 이번 시즌 운영 시간표 12곳 입력 (버전, 적용 기간)
- [ ] 운영 시간·공식 현황·웹캠 링크가 이번 시즌 기준인지 확인, 못 한 리조트는 운영 시간 숨김 (R34)
- [ ] 강풍 안내 문구에 리프트 운휴 예측이나 안전 기준 표현이 없는지 확인 (R35)
- [ ] 강풍 안내 동작 (R35): 기준값 바로 아래·같음·위, 정각이 아닌 현재 시각(예: 10:30)에 지금 시간대 예보 포함, 폐장 시각 경계(예: 22:30 폐장에 22시 예보 포함), 심야 구간 포함, 시간표 미확인 시 "향후 24시간" 표기, 예보 없음·조회 실패 시 안내 안 뜸
- [ ] 운영 시간 숨김 (R34): `verifiedSeason` 없는 리조트, `verifiedSeason`이 지난 시즌인 리조트, 적용 기간 밖 날짜에서 숨기고 링크만 보임, 휴장으로 표시되지 않음
- [ ] 공유 이미지 (R31): 지도 있는 기록과 지도 없는 기록(목록형) 모두에서 생성·공유 성공, 이미지 합계가 하루 기록 합계와 일치
- [ ] 공유 이미지에 GPS 좌표·경로·위치 메타데이터(EXIF 위치 포함)가 없는지 확인 (R31)
- [ ] 슬로프 이름 표시가 꺼진 상태로 제출되는지 확인 (켜기는 출시 후, 2장 R9 기준 통과 리조트부터)
- [ ] OSM 가공 데이터 공개, 앱 안 출처 표시

**개인정보·법**
- [ ] 위치정보지원센터 확인 결과 반영
- [ ] 개인정보처리방침: 수집 항목, 크루 공유, 익명 집계, Firebase Authentication 국외 이전(미국)
- [ ] 앱스토어 개인정보 항목이 실제 전송과 일치 (3장 R17 프록시 확인)
- [ ] 표본 함수 요청 로그 제외(`cloud_run_revision`, `submitsample`, `run.googleapis.com/requests`), Hosting Cloud Logging 연동 끔, 데이터 액세스 감사 로그 끔, 다른 싱크 없음 확인
