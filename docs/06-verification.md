# 06. 검증

작성: 2026-11-08 · 깊이: 가볍게 · 상태: 사용 중 (2026-11-23 기준)

무엇이 동작하는지, 위험한 가정이 맞는지, 업데이트를 내도 되는지를 어떻게 확인할지 정한다. 앞 문서에서 "06에서 정함"으로 미룬 기준값도 여기서 제안한다. 확인한 결과와 남은 확인 일은 todo에 적는다.

## 1. 검증 방법 네 가지

| 방법 | 언제 | 무엇을 |
| --- | --- | --- |
| **기록 재생 테스트** | 판정 코드를 고칠 때마다 | 테스터 기록 파일(R22)과 기대 결과(직접 센 하강 횟수, 대기 시간)를 짝지어 저장. 코드가 같은 결과를 내는지 자동 확인. 안드로이드도 같은 파일로 확인(R48) |
| **현장 테스트** | 시즌 중 TestFlight 테스터 | 실제 스키장에서 기록 정확도, 보존, 배터리 |

| **수동 점검** | 업데이트 제출 전 | 화면, 권한, 접근성, 심사 요건 (6장) |

## 6. 업데이트 제출 전 반복 확인

App Store에 업데이트를 낼 때마다 아래를 확인한다. 한 번만 하면 되는 일과 확인 결과는 todo에 적는다.

**빌드**
- Release 설정으로 아카이브하고 R22 테스트 기록 내보내기가 없는지 (R22)
- 기록 재생 테스트와 전체 단위 테스트 통과
- 접근성 코드 점검(3장 R21)

**데이터·서버 설정**
- `config.json`: 슬로프 이름(`slopeNames`)은 2장 R9 기준을 통과한 리조트만, `liftWait`는 2장 R10 기준을 통과했을 때만 켜져 있는지 (R9, R32)
- 시간표를 고쳤으면 버전을 올렸는지, `verifiedSeason`은 이번 시즌 공식 안내와 대조한 시간표에만 있는지, 확인 안 된 리조트는 운영 시간이 숨고 휴장으로 표시되지 않는지 (R7, R34)
