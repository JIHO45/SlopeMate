# 06. 검증

작성: 2026-11-08 · 깊이: 가볍게 · 상태: 검토 대기

무엇이 동작하는지, 위험한 가정이 맞는지, 출시해도 되는지를 어떻게 확인할지 정한다. 앞 문서에서 "06에서 정함"으로 미룬 기준값도 여기서 제안한다.

## 1. 검증 방법 네 가지

| 방법 | 언제 | 무엇을 |
| --- | --- | --- |
| **기록 재생 테스트** | 판정 코드를 고칠 때마다 | 테스터 기록 파일(R22)과 기대 결과(직접 센 하강 횟수, 대기 시간)를 짝지어 저장. 코드가 같은 결과를 내는지 자동 확인. 안드로이드도 같은 파일로 확인(R48) |
| **현장 테스트** | 11월 말 개장부터 TestFlight로 | 실제 스키장에서 기록 정확도, 보존, 배터리 |

## 6. 출시 체크리스트

2.0(11월 말)에는 아래 항목을 모두 확인한다. 2.0에 크루·서버가 들어가므로 서버 항목도 포함한다.

**데이터**
- [ ] 이번 시즌 운영 시간표 12곳 입력 (버전, 적용 기간)
- [ ] 운영 시간·공식 현황·웹캠 링크가 이번 시즌 기준인지 확인, 못 한 리조트는 운영 시간 숨김 (R34)

- [ ] 강풍 안내 동작 (R35): 기준값 바로 아래·같음·위, 정각이 아닌 현재 시각(예: 10:30)에 지금 시간대 예보 포함, 폐장 시각 경계(예: 22:30 폐장에 22시 예보 포함), 심야 구간 포함, 시간표 미확인 시 "향후 24시간" 표기, 예보 없음·조회 실패 시 안내 안 뜸
