# 03. 요구사항

작성: 2026-11-08 · 깊이: 충실히 · 상태: 승인 (2026-11-08)

이 문서는 **트래킹 앱 첫 출시(버전 2.0)** 의 범위를 정한다. 기존 앱스토어 등록(SlopeMate)을 업데이트로 이어 쓴다. **이번 시즌 개장(2026년 11월 말)에 P0 전체를 2.0으로 출시한다.** 슬로프 이름 표시(R9)만 출시 후 리조트별로 켠다(8장). 01-idea의 아이디어와 02-market의 결론을 바탕으로 한다.

**출시 기준 (MMP):** 2.0은 국내 시즌권자가 방문을 준비하고, 안심하고 기록하며, 하루 결과를 돌아보고 공유하고, 시즌 활동을 이어갈 수 있는 완성품을 목표로 한다. 기능은 이 경험에 필요한 가치와 신뢰도를 기준으로 포함한다. 슬로프 이름·대기 합계는 정확도 기준을 통과한 뒤 공개한다. 예상 설질은 관측 결과와 구분해 "예상"과 계산 근거를 표시하고, 시즌 중 현장 평가와 비교해 차이가 크면 시즌 중에도 업데이트로 규칙을 고친다. 본격 보정은 시즌 후에 한다.

**수익 (2026-11-14):** 기록과 기본 기능은 무료다. 더 깊이 보는 기능(3D 지도, 고화질 공유 영상, 하강 상세 분석, 내 리프트 대기, 시즌 결산)은 **시즌 이용권(R54)** 으로 연다. 모두가 보낸 표본으로 만드는 정보는 무료다.

## 1. 문제

스키장에 자주 가는 사람은 오늘 몇 번, 어느 슬로프를 탔는지, 이번 시즌 얼마나 탔는지 남기고 싶다. 해외 트래킹 앱은 국내 스키장의 슬로프와 야간·심야 운영을 잘 다루지 않고, 국내 앱은 기록보다 커뮤니티나 랭킹 점수에 집중한다. 그래서 국내 스키어의 시즌 기록은 기억과 사진에 흩어져 있다.

## 4. 사용자 시나리오

**시나리오 A: 시즌권자의 평일 야간**
지수는 곤지암 시즌권자다. 처음 앱을 열어 홈 리조트로 곤지암과 가끔 가는 지산을 고르고, 시즌권 가격을 넣었다. 퇴근 후 19시에 도착해 기록을 시작하고 휴대폰을 주머니에 넣는다. 리프트에서 잠금 화면의 기록 카드를 눌러 앱을 열자, 맨 위에 "방금: 레드 슬로프 · 설질?" 칸이 있어 "아이스"를 누른다. 22시 반에 기록을 끝내자 "야간 · 14회 · 18.2km"와 하강 목록이 나온다. 시즌 화면에는 "9일째 · 1회 방문당 31,000원"이 보인다.

**시나리오 B: 기록 중 앱이 종료됨**
민호는 점심을 먹다가 휴대폰 배터리가 꺼졌다. 충전 후 앱을 열면 꺼지기 직전까지의 기록이 남아 있고, "기록이 중간에 끊겼어요. 이어서 기록할까요?"가 뜬다. 끊긴 시간은 "기록 없음"으로 보인다.

**시나리오 C: 크루 비교**
지수는 크루 "목요야간"을 만들고 초대 링크를 단톡방에 올린다. 크루원 4명이 들어오자 크루 화면에 이번 시즌 방문일, 횟수, 거리 순위가 나온다. 가입 화면에서 "가입 전 이번 시즌 기록도 크루에 공유됩니다"라는 안내를 본다.

**시나리오 D: 다른 리조트 방문**
지수가 주말에 하이원에 간다. 기록을 시작할 때 이번 기록의 리조트만 하이원으로 바꾼다. 홈 리조트 목록은 그대로다. 하이원의 슬로프 이름이 아직 켜지지 않았다면 슬로프 이름 없이 기록되고, 주간·야간 구분과 횟수·거리는 그대로 나온다. 시즌권 본전 계산에는 곤지암 방문만 들어간다.

## 6. 요구사항

### 리조트별 지원 범위

리조트 수를 미리 제한하지 않는다. 기능마다 필요한 데이터가 달라서, 기능별로 켜는 조건을 둔다. 리조트 데이터 이용 문의의 결과는 실시간 슬로프 현황(P1 이후)에만 영향을 준다.

| 기능 | 켜지는 리조트 | 필요한 데이터 | 리조트 허락 |
| --- | --- | --- | --- |
| 기록, D1 시즌권 본전, D5 크루 | 모든 국내 리조트 | 없음 | 필요 없음 |
| D2 주간·야간·심야 세션 | 시간표를 입력한 리조트 (출시 때 전체 목표) | 리조트가 공개한 운영 시간을 손으로 입력 | 필요 없음 |
| R9 슬로프 이름 표시 (하강에 자동으로 붙이는 이름) | 현장 테스트를 통과한 리조트부터 하나씩 | OpenStreetMap 슬로프·리프트 데이터 | 필요 없음 (출처 표시) |
| R50 하루 기록 지도·움직임 재생 | OSM 슬로프·리프트 데이터가 있는 리조트 | OpenStreetMap 슬로프·리프트 데이터. 지형 바탕은 Copernicus DEM 고도 데이터(없어도 지도는 동작) | 필요 없음 (출처 표시) |
| D3 설질, D4 리프트 대기 수집 | 기기 안에서 슬로프·리프트를 식별할 수 있는 리조트 | OpenStreetMap | 필요 없음 |
| 실시간 슬로프 현황 (열림/닫힘) | 서면으로 허락한 리조트만 | 리조트 홈페이지 | **필요함** |

우선순위: **P0** 첫 출시에 반드시 필요(위 출시 기준의 경험을 완성하는 것) · **P1** 출시 직후 · **P2** 사용자가 모인 뒤, 지금은 설계만 고려

### P0: 이번 시즌 첫 출시

**기록**

| ID | 요구사항 | 수용 기준 |
| --- | --- | --- |
| R1 | **홈 리조트 직접 선택** | 첫 실행 때 국내 리조트 목록에서 홈 리조트를 **여러 개** 고를 수 있다. 기록을 시작할 때 홈 리조트 중 하나를 고르고, 마지막으로 기록한 리조트가 기본값이다. 목록에 없는 리조트도 이번 기록에만 고를 수 있다. GPS로 리조트를 미리 고르거나 확인하지 않는다. |
| R51 | **온보딩** | **처음 열 때:** O1 환영 1화면(시작하면 하강과 리프트를 자동으로 구분, 야간·심야 기록, 시즌권 본전, "GPS 기록은 우리 서버로 보내지 않아요") → S1 홈 리조트 선택. S1에서 고르거나 "자주 가는 곳이 없어요"를 누른 순간 온보딩 완료이며, 일반 진입은 홈(S2)으로, 초대 링크로 들어왔으면 바로 S16으로 간다. 권한은 온보딩에서 묻지 않는다. **시즌권:** 등록 때 대상 리조트는 홈 리조트를 자동으로 고르지 않고 목록 위에 후보로만 보여준다. **첫 기록 안내:** 따로 몰아서 띄우지 않는다. 종료 방법은 종료 버튼("길게 눌러 종료")에 있다. **다시 보기:** 설정의 "처음 안내 다시 보기"는 O1 설명만 다시 보여주고, 홈 리조트·동의·완료 상태를 초기화하거나 권한을 다시 묻지 않는다. |
| R2 | **기록 시작·종료** | 시작 버튼 한 번으로 기록이 시작된다. 화면이 꺼지거나 다른 앱을 써도 기록이 계속된다. 종료 버튼으로 끝낸다. |
| R3 | **라이딩·리프트 자동 구분** | 5장 규칙으로 하강을 나누고, 하강마다 시작 시각, 거리, 고도차, 최고·평균 속도를 남긴다. G3 기준을 만족한다. |
| R4 | **기록 보존** | **받은 위치 데이터**는 받는 즉시 기기에 저장해, 강제 종료·시스템 종료·방전 시 잃는 범위가 최대 1분 (제안값)이다. 휴대폰이나 앱이 꺼져 있어 **받지 못한 시간**은 이 약속에 포함되지 않으며, "기록 없음" 구간으로 표시하고 거리를 추정해 채우지 않는다. 다시 열면 이어서 기록할지 묻고, 이어서 기록해도 하강이 중복되지 않는다. 앱 업데이트 후에도 기록이 남는다. 저장 공간이 부족하면 기록 시작 전에 알리고, 기록 중 저장에 실패하면 기록을 멈추고 알린다. 서버 연결 없이도 기록된다. |
| R49 | **종료를 잊은 기록 대응** | 사용자가 종료하지 않고 스키장을 떠나도 기록이 틀어지지 않게 한다. (1) **차량 이동 제외:** 동작 센서가 차량 이동으로 판단한 구간은 하강·거리에 넣지 않는다. 동작 권한이 없으면 제외하지 못하고 (2) 알림에 맡긴다. (2) **알림:** 마지막 하강(없으면 기록 시작) 뒤 60분 동안 하강이 없거나, 기록에 고른 리조트에서 5km 이상 벗어나면 "아직 기록 중이에요" 로컬 알림을 보낸다(제안값). 조건마다 한 번만 보내고, 새 하강이 생기면 다시 보낼 수 있다. 알림은 기기 안에서 만들고 서버를 거치지 않는다. 알림 권한을 거부해도 기록은 된다. 리조트까지의 거리는 알림에만 쓰고 기록의 리조트 값을 고르거나 확인하는 데 쓰지 않는다(R1). (3) **영업일 끝에 닫기:** 영업일 끝(06:00)이 지난 뒤 첫 위치를 받거나 앱이 실행되면, 마지막 위치점 시각으로 기록을 끝낸다. 시간표를 쓰지 않으므로 자동 종료(R30)와 다르다. |
| R5 | **하루 기록 화면** | 합계(횟수, 거리, 고도차, 최고 속도)와 하강 목록을 보여준다. 세션이 있으면 세션별로 나눈다. |
| R50 | **하루 기록 지도, 움직임 재생, 동영상 공유** | 하루 기록 화면은 **전체 화면 지도**다. 처음 열면 리조트 전체 슬로프·리프트가 한 화면에 들어오고, 두 손가락으로 확대·이동할 수 있다. 리조트 슬로프는 **난이도 색 실선**(초급 초록, 중급 파랑, 상급 빨강, 최상급 검정, 난이도 정보가 없으면 회색), 리프트는 점선이다. **지도 표시 메뉴**에서 슬로프와 리프트를 각각 끄고 켤 수 있고(기본 둘 다 켜짐, 선택을 기억) 난이도 색 범례를 본다. **슬로프 선을 누르면** OSM 이름과 난이도를 작은 말풍선으로 보여 준다(이름이 없으면 "이름 정보 없음"). 사용자가 직접 누른 슬로프의 이름이라 R9 통과 여부와 상관없이 모든 리조트에서 보인다. 그 위에 그날 경로를 겹치고, 재생하면 시간 순서대로 이동을 애니메이션으로 보여준다(하루를 약 30초로 압축, 재생·일시정지, 시간 막대로 원하는 시각 이동). 내 경로에서 하강은 강조색 실선, 탄 리프트는 점선이고 "기록 없음" 구간은 선을 잇지 않는다. 합계와 하강 목록은 지도 위 **아래 시트**에 둔다(기본 약 25%, 끌어서 50%). **공유:** 재생 애니메이션을 10~15초 세로 동영상으로 만들어 공유 시트로 보낸다. 동영상은 공유를 누를 때만 만들고 저장해 두지 않는다. 동영상에는 리조트 슬로프·리프트 선을 그리지 않는다(지형 바탕과 내 경로만). 공유 전에 "오늘 경로가 담겨요"라고 알린다. **성능:** 기록을 끝낼 때 경로를 줄여 계산해 판정 기준 버전과 함께 기기에 저장하고, 하루 기록을 열면 저장된 경로로 바로 그린다. 판정 기준이 바뀌면 다시 계산한다. **데이터:** 지도는 앱에 내장한 OSM 가공 데이터로 기기 안에서 그리고 바탕 지도 타일을 받지 않는다(인터넷 없이 동작, 위치가 기기 밖으로 나가지 않음). 하강에 자동으로 붙이는 슬로프 이름은 R9 기준을 통과한 리조트에서만 표시한다. OSM 데이터가 없거나 부족한 리조트는 지도 대신 기존 목록 화면을 보여준다. **지형 바탕:** 슬로프 선 아래에 지형 음영과 등고선을 그린다. 앱에 내장한 리조트별 고도 격자(Copernicus DEM GLO-30, 약 30m 간격)로 기기 안에서 계산하고, 화면과 동영상이 같은 바탕을 쓴다. 고도 격자가 없는 리조트는 바탕 없이 그린다. **3D 보기 (시즌 이용권, R54):** 고도 격자가 있는 리조트는 화면의 지도를 3D 지형으로 바꿔 돌리고 기울여 볼 수 있다(기본은 2D, 기기 안에서 그리고 타일을 받지 않음). 3D는 겨울 산 지형에 슬로프를 흰 눈 띠로 보여 주고 그 가운데에 난이도 색 선을 긋는다. 지도 위에 적설 수치·슬로프 번호·시설 아이콘은 올리지 않는다. 밝게·어둡게는 시스템 설정을 따른다. 재생·시간 막대·하강 목록은 2D와 같이 쓴다. 공유 동영상은 2D다. **동영상 화질:** 무료는 720×1280에 SlopeMate 워터마크, 시즌 이용권은 1080×1920에 워터마크 없음(출처 표기는 둘 다 넣음). 지도와 동영상에 OSM 출처를, 지형 바탕을 그리면 고도 데이터 출처도 표시한다. |
| R52 | **하강 상세 분석 (시즌 이용권)** | 하루 기록 화면에서 하강을 고른 뒤 "자세히"로 연다. 그 하강의 시간에 따른 속도·고도 그래프, 멈춘 시간을 뺀 평균 속도를 보여준다. 슬로프 이름이 켜진 리조트(R9)에서는 같은 슬로프의 이번 시즌 횟수와 최고·평균 속도 변화를 함께 보여준다. 하강 목록의 기본 숫자(R3: 시각, 거리, 고도차, 최고·평균 속도)는 무료로 그대로 둔다. 기기 안 기록만 쓰고 서버로 보내지 않는다. |

| R7 | **D2 주간·야간·심야 세션** | 리조트별 날짜별 운영 시간표로 각 하강을 세션에 배정한다. 시간표 밖의 하강은 "미분류"로 둔다. 시간표가 없거나 오래된 리조트는 세션을 나누지 않는다. 시간표를 고치면 지난 기록도 다시 분류된다. 모든 리조트의 시간표를 리조트가 공개한 정보에서 손으로 입력해 준비한다(자동 수집하지 않음). 이 준비가 요구사항에 포함된다. |
| R8 | **D1 시즌권 본전 계산** | 시즌권을 **여러 장** 등록할 수 있다. 시즌권마다 이름, 가격, 대상 리조트(여러 개 가능)를 입력하면 "1회 방문당 금액"과 "리프트권으로 샀다면 쓴 금액"을 보여준다. 리프트권 금액은 앱에 넣은 리조트별 하루 리프트권 주말 정가로, 방문한 날마다 그 리조트 값을 더한다(같은 날 두 리조트면 비싼 쪽 하루). 2장 이상이면 전체 합계도 보여준다(5장 규칙). 등록한 시즌권이 없으면 카드를 숨긴다. 대상 리조트 방문일이 0일인 시즌권은 계산하지 않는다. |

| R53 | **시즌 결산 (시즌 이용권)** | 시즌 화면에서 연다. 방문일, 하강 횟수, 거리, 고도차, 세션별(주간·야간·심야) 비율, 가장 많이 간 리조트, 가장 많이 탄 날, 가장 많이 탄 슬로프(슬로프 이름이 켜진 리조트만), 시즌권 본전(R8, 등록했을 때)을 카드 여러 장으로 보여준다. 시즌 중에는 "지금까지"로, 시즌이 끝나면(4월 30일) 최종 결산으로 표시한다. 카드는 이미지로 공유할 수 있고 GPS 좌표·경로·위치 메타데이터는 넣지 않는다(R31과 같음). 이용권이 없으면 첫 카드(방문일·횟수·거리, 무료 시즌 기록과 같은 숫자)만 보여주고 나머지는 잠근다. |
| R9 | **슬로프 이름 표시 (조건부)** | OSM 기반 슬로프 데이터로 하강에 슬로프 이름을 붙인다. 난이도는 데이터에 있을 때만 보여준다. 애매하면 "알 수 없는 슬로프"로 둔다. 현장 테스트에서 **이름 정답률과 이름을 붙인 비율**이 둘 다 기준을 넘을 때만 리조트별로 켠다 (기준은 06-verification). 표시를 꺼도 D3에 쓸 슬로프 식별은 기기 안에서 계속한다. OSM 출처를 앱 안에 표시한다. 이 조건은 하강에 자동으로 이름을 붙이는 판정에만 적용한다. 지도에서 사용자가 직접 누른 슬로프의 OSM 이름 표시(R50)는 판정이 아니므로 모든 리조트에서 보인다. |

## 8. 일정 고려

- 국내 스키장은 11월 하순부터 순차 개장한다. 트래킹은 눈 위에서만 검증할 수 있다.
- **출시 순서: 개장(11월 말)에 P0 전체를 2.0으로 낸다.** 슬로프 이름(R9)은 코드는 넣되 표시를 꺼 두고, 리조트별로 현장 검증을 통과하면 서버 설정 파일로 켠다. 늦어지면 기능을 빼지 않고 출시를 다음 시즌으로 미룬다. 테스터는 TestFlight로 한발 앞선 빌드를 쓴다. 11월 25일쯤 심사 제출을 목표로 하고, TestFlight 외부 테스트 심사와 앱스토어 심사 시간을 일정에 더한다. 심사자는 스키장에 갈 수 없으므로 녹화 영상이나 시연용 재생 기능 같은 심사 자료가 필요할 수 있다.
- **테스터가 검증하려면 기록을 받아 볼 방법이 필요하다.** GPS 기록은 우리 서버로 오지 않으므로, TestFlight 빌드에만 테스터가 직접 자기 기록 파일을 내보내 보내 주는 기능을 둔다(R22). 테스터는 직접 센 하강 횟수와 리프트 대기 시간도 함께 적어 보낸다.
- P0가 35개(R1~R23, R31, R33, R34, R35, R36, R39, R49, R50, R51, R52, R53, R54)이고, 계정·크루(R13~R16)에 서버가 필요하다. 시즌 이용권(R54)은 인앱 구매 상품을 앱과 함께 심사받으므로 유료 앱 계약(완료)과 App Store Small Business Program(신청함, 승인 대기)을 제출 전에 확인한다. 주 40시간 1인 개발 기준의 일정은 05-design에서 기능별로 추정한다.
- **늦어질 때:** 기능을 잘라 내지 않는다. P0 전체가 준비되지 않으면 출시를 다음 시즌으로 미룬다(2026-11-09 결정).
