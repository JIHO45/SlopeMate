- **기각한 대안:** GPS로 리조트를 자동 판별해 서버로 보내기 (개인위치정보가 되어 신고·동의·기록 보관 의무가 생김)

## 2026-11-08 설질 평가는 앱 안 칸으로 (Live Activity에는 넣지 않음)
- **결정:** 설질 평가 칸은 앱 안 기록 중 화면 맨 위에만 둔다. Live Activity는 경과 시간·하강 횟수·거리만 보여주고 버튼을 넣지 않으며, 누르면 기록 중 화면이 열린다.
- **이유:** 버튼이 있는 Live Activity는 사용자에게 익숙하지 않다. Apple 지침은 Live Activity를 상태 표시 중심으로 본다. 장갑 낀 손으로 잘못 눌러 설질 데이터가 오염될 수 있다. 초기 설질 데이터는 양보다 정확도가 중요하다.
- **기각한 대안:** Live Activity에 설질 버튼 넣기, 리프트 탑승 시 알림으로 묻기
- **다시 볼 조건:** 출시 후 응답률이 너무 낮으면 Live Activity 버튼 방식을 일부 사용자에게 시험한다.

## 2026-11-08 날씨 앱 코드는 지우고 프로젝트 껍데기와 리조트 데이터는 남김

## 2026-11-08 리조트 기본 데이터는 앱 내장 JSON

## 2026-11-08 끝나지 않은 기록의 자동 재개 기준 (R4, S7)
- **결정:** 앱이 실행될 때 끝나지 않은 기록이 있으면 아래 순서로 처리한다.
  1. 영업일이 지났으면 마지막 위치점부터 "기록 없음"으로 남기고 끝낸다.
  2. iOS가 위치 이벤트로 다시 실행했거나, 같은 영업일에 마지막 위치점에서 10분(제안값) 안이면 묻지 않고 이어서 기록한다. 화면에 "자동으로 이어서 기록 중, 끊긴 n분은 기록 없음"과 종료 버튼을 보여준다.
  3. 권한 때문에 멈춰 있던 기록이나 10분보다 오래 끊긴 기록은 S7로 묻는다.
  4. 사용자가 종료한 기록은 끝난 기록이라 재개하지 않는다. (기록 일시정지 기능은 없다.)
- **이유:** 강제 종료와 시스템 종료를 iOS에서 확실히 구분할 수 없다. 짧게 끊긴 경우는 이어 가는 것이 사용자 의도에 가깝고, 자동 재개를 화면에 알리고 바로 끝낼 수 있게 해 잘못 이어진 경우를 되돌린다.
- **기각한 대안:** 위치 재실행 신호(`launchOptions[.location]`)가 있을 때만 자동 재개(신호가 없으면 백그라운드 기록이 끊김), 항상 S7로 묻기(백그라운드에서 물을 수 없어 기록이 끊김)
- **확인:** 10분 기준과 위치 재실행 신호는 TestFlight 현장 기록의 재시작 이유(`system`, `auto`, `user`)로 확인한다.

## 2026-11-08 M1 기록 엔진 구현 방식
- **결정:** 하강은 DB에 저장하지 않고 위치점에서 매번 계산한다(슬로프 이름·설질이 붙는 M2·M3에서 하강 테이블 추가). 같은 수신 구간(seq) 안에서도 기압 고도와 GPS 고도는 섞지 않는다. R22 내보내기는 `TestFlight` 빌드 설정(`TESTFLIGHT` 조건)과 Debug에만 들어가고 Release에는 없다. TestFlight 아카이브는 `-configuration TestFlight`로 하고 "TestFlight Internal Only"로 올린다.
- **이유:** 판정 기준을 바꾸면 지난 기록이 자동으로 다시 계산된다. 기준이 다른 고도를 빼면 가짜 하강이 생긴다. 같은 빌드를 앱스토어에 올려도 테스트 기능이 들어가지 않는다.
- **기각한 대안:** 하강 테이블을 지금 만들기, Release에 `TESTFLIGHT`를 켜고 출시 때 끄기(사람이 기억해야 함)
- **검토:** Codex 독립 검토(high) 2회, 지적 14건 반영
