# SlopeMate 슬로프 현황 데이터 조사

확인일: 2026-11-07 · 작성: 박지호

> 법률 자문이 아닌 사전 조사입니다. 슬로프 현황을 앱에 넣기 전에 개별 약관의 적용 여부를 전문가에게 확인받아야 합니다.

---

## 1. 요약

**결론: 리조트의 서면 허락 없이 슬로프 현황을 수집해 앱에서 다시 보여주는 방식은 유료 기능의 기반으로 삼지 않는다.** 먼저 2~3곳에서 데이터 이용 허락을 받는다. 허락받지 못한 리조트는 공식 현황 페이지 링크로 연결한다.

- 12곳 중 크롤링이나 스크래핑을 약관에서 직접 금지한 곳은 확인되지 않았다.
- 그러나 약관을 확인한 10곳 모두 서비스에서 얻은 정보를 허락 없이 복제하거나 이용하는 것을 제한한다.
    - 이 중 9곳은 영리·상업적 이용 금지를 명시한다. 지산은 회사에 지식재산권이 있는 정보로 범위를 한정한다.
- robots.txt가 허용하는 것은 수집뿐이다. 수집한 데이터를 유료 앱에서 다시 배포해도 된다는 허락은 아니다.
- 무료로 출시하거나 출처를 표시해도 면책되지 않는다. 데이터베이스제작자의 권리(저작권법 제93조)와 부정경쟁방지법은 따로 검토해야 한다.
- 날씨와 예상 설질처럼 우리가 직접 만드는 데이터는 12곳 모두에 제공한다(설질 점수는 사용자가 모인 뒤). 슬로프 현황은 허락받은 리조트부터 늘려 간다.

---

## 2. 조사 범위와 방법

2026-11-07에 앱이 지원하는 12개 리조트의 슬로프 현황 페이지를 조사했다. 비시즌이라 실제 오픈 데이터는 대부분 비어 있었다.

- **robots.txt:** 각 도메인의 `/robots.txt`를 직접 받아 확인했다.
- **데이터 형식:** 현황 페이지의 HTML 응답과 브라우저 네트워크 요청을 확인했다.
- **약관:** 각 사이트 하단의 이용약관을 받아 다음 키워드로 조항을 찾았다.
    - 키워드: 복제, 영리, 상업, 크롤, 자동화, 로봇
    - 찾은 문장은 원문과 다시 대조했다.
- **차단된 요청은 우회하지 않았다.**
    - 지산: robots.txt 요청부터 차단됨
    - 엘리시안: 약관 API가 403을 반환함
    - 두 곳 모두 차단된 상태 그대로 기록했다.

**한계**
- 약관 전문을 법률적으로 해석하지는 않았다.
- 회원가입 단계에서만 볼 수 있는 약관(용평)은 확인하지 못했다.
- 리조트에 별도 데이터 이용 정책이나 공식 API가 있는지는 문의하지 않았다.

### 데이터 형식 참고

응답 형식이 적법성을 결정하지는 않는다. **브라우저에서 호출할 수 있는 API라고 해서 제3자가 상업적으로 다시 써도 되도록 허가된 API는 아니다.**

데이터 형식은 기술 난이도만 보여준다. 쉬운 순서는 다음과 같다.
1. JS 변수, JSON, Nuxt 내장 데이터
2. 서버 HTML
3. 이미지

## 5. 데이터 공급 전략

**수집 난이도보다 공급 안정성을 먼저 본다.** 이 서비스가 가장 크게 의존하는 것은 파싱 코드가 아니라 지속적으로 쓸 수 있는 데이터 공급원이다.

1. **운영 중인 리조트 전체에 한 번에 문의한다.** 같은 문의서를 쓰되 리조트별로 이름과 현황 페이지만 바꾼다. 문의서는 보내기 전에 확정한다. 응답이 온 순서대로 허락받은 리조트부터 현황을 붙인다.
2. **허락받기 전에는** 공식 현황 페이지 링크만 제공한다.
3. **12곳 공통으로는** 자체 데이터(날씨, 예상 설질, 강풍 안내)를 제공해 리조트 화면과 비교 화면의 가치를 유지한다.
4. **지산의 차단은 우회하지 않는다.** 에덴밸리는 스키장 운영 여부를 먼저 확인한다.

### 리조트 문의 범위 (서면으로 받을 것)

앱에 유료 기능(시즌 이용권)이 있으므로 처음부터 유료 기능 범위까지 포함해서 묻는다. 무료 기능 기준으로 허락받으면 유료 기능에 쓸 때 다시 문의해야 한다.

- 사용 항목: 슬로프명, 운영 상태, 공식 갱신 시각
- 공식 이미지와 설명문은 복제하지 않음
- 출처와 원문 링크를 표시함
- 합의한 조회 주기를 지킴
- **허용 여부를 받아야 할 항목:**
    - 유료 기능(시즌 이용권)에서 표시
    - 가공 (예상 설질·설질 정보와 결합 등)
    - 상태 변경 알림
    - 이력 저장
- 리조트에 줄 수 있는 것: 앱 안 리조트 노출, 공식 링크를 통한 트래픽, 예약 페이지 연결

## 6. 상태 표시와 실패 처리 원칙

**수집에 실패했을 때 CLOSED로 바꾸거나, 예전 OPEN을 계속 보여주지 않는다.** 오래된 상태를 최신처럼 보여주는 문제는 법률 문제만큼 서비스 신뢰에 치명적이다.

| 항목 | 의미 | 표시 규칙 |
| --- | --- | --- |
| 공식 갱신 시각 | 원본이 제공하는 갱신 시각 | 원본에 있을 때만 표시 |
| 마지막 수집 성공 시각 | 앱 서버가 마지막으로 확인한 시각 | 항상 표시 |
| 상태 미확인 | 수집 실패, 또는 유효기간 초과 | OPEN/CLOSED 대신 이 상태로 표시 |
| 운영 상태 | 원본의 세부 상태 (정설, 일시 중단, 운영 예정 등) | OPEN/CLOSED 두 가지로 뭉개지 않음 |

- 페이지 구조가 바뀌었거나 차단이 감지된 리조트는 그 리조트만 즉시 수집과 표시를 멈출 수 있어야 한다.

> - 공식 슬로프 맵 이미지, 사진, 설명문은 복제하지 않습니다. 슬로프 맵은 자체 디자인으로 제작합니다.
> - 모든 화면에 "[리조트명] 공식 홈페이지" 출처와 원문 링크를 표시합니다.
> - 운영 시간 중 [30]분 간격 이하로만 조회하며, 원하시는 주기나 방식(API, 파일 제공 등)이 있으면 그에 따르겠습니다.
> - 정보를 확인하지 못한 경우에는 이전 상태를 그대로 보여주지 않고 "상태 미확인"으로 표시합니다.
> - 요청하시면 언제든지 표시를 중단합니다.
>
> **허락 여부를 여쭙고 싶은 범위**
> 1. 앱의 무료 기능과 유료 기능(시즌 이용권)에서 위 정보 표시
